5. Complete Codebase Module Inventory

Core Package (faultshield/)

  • faultshield/config.py: Centralizes simulation timestep (0.05s), robot kinematic bounds, sensor noise parameters, SIM anomaly thresholds, Safety Governor limits (GOVERNOR_MAX_DECISION_TTL_SEC = 0.50s, GOVERNOR_CRITICAL_STOP_DISTANCE = 0.42m), and Nebius Token Factory defaults.
  • faultshield/core/world.py: Implements RectObstacle and WarehouseMap with parametric ray-segment intersection (_ray_segment_intersect) for 24-beam LiDAR simulation and exact circular-robot collision detection.
  • faultshield/core/robot.py: Implements DifferentialDriveRobot with acceleration-limited midpoint Euler integration and collision immobilization.
  • faultshield/core/sensors.py: Implements SensorSuite producing TelemetryPacket (LidarReading, OdometryReading, IMUReading) with seeded stochastic Gaussian noise and wheel slip.
  • faultshield/core/controller.py: Implements NavigationController, a reactive potential-field controller combining goal attraction and inverse-square LiDAR obstacle repulsion.
  • faultshield/faults/injector.py & scenarios.py: Implements FaultInjector and the 5 standardized BENCHMARK_SCENARIOS.
  • faultshield/integrity/monitor.py: Implements SensorIntegrityMonitor, executing deterministic checks on telemetry freshness, consecutive identical LiDAR frames, IMU-vs-Odometry yaw rate divergence, and range saturation.
  • faultshield/agent/nemotron.py & prompts.py: Implements NemotronRecoveryAgent with OpenAI-compatible client calls to Nebius Token Factory, regex JSON extraction, per-fault live response caching, and deterministic offline fallback.
  • faultshield/safety/governor.py: Implements SafetyGovernor, enforcing TTL expiration, action allowlisting, recovery speed clamping, and critical obstacle proximity overrides.
  • faultshield/benchmark/runner.py & metrics.py: Implements BenchmarkRunner, EpisodeMetrics, and compute_benchmark_summary.
  • faultshield/visualization/plotter.py: Builds Plotly figures for the 2D warehouse floorplan, scrubbed LiDAR ray fan, telemetry timelines, and 4-variant grouped bar charts.

6. Key Technical Findings from Project Audit

IMPORTANT
During the full code review, we identified three subtle behavioral mechanics in the current implementation that affect benchmark numbers in results/benchmark_summary.csv:
  1. Active AI Decision Aging Across Subsequent Timesteps (runner.py L229-L245):
    • When an AI decision arrives with a small network delay (e.g., ai_delay_sec = 0.1s in exp2_frozen_lidar, total latency 0.18s), the Safety Governor initially approves it (ACCEPTED) because age = 0.18s <= 0.50s.
    • However, because active_ai_decision remains stored while executing continuous actions (like REVERSE_SLOWLY), age = current_sim_time - ai_decision.dispatch_timestamp increases by 0.05s on every subsequent simulation step.
    • Seven steps later (0.35s after arrival), age exceeds 0.50s, causing the Governor to mark the already-accepted ongoing maneuver as REJECTED_STALE, clear active_ai_decision, and re-query Nemotron on the next tick. This explains why exp2_frozen_lidar logs 26 stale rejections even though its network delay is only 0.1s.
  2. Reactive Potential-Field Local Minima in Warehouse Layout (controller.py L68-L95):
    • In results/benchmark_summary.csv, Goal Completion (%) is 0.0% even in exp1_healthy (Mean Duration = 30.0s, Path Length = 8.74m).
    • Why? The robot starts at (1.5, 1.5) aiming for (10.5, 8.5), and the potential-field repulsion from Rack_A1, Rack_A2, and Pillar_Center balances the attractive force or causes slow contouring that does not reach within 0.5m of (10.5, 8.5) before the 600-step (30s) limit expires.
  3. Action Set Mapping Between Warehouse Engine and Corridor 3D Engine (app.py L285-L291):
    • NemotronRecoveryAgent outputs one of the 7 warehouse actions (e.g., REVERSE_SLOWLY, RECALIBRATE_IMU, SAFE_STOP_AND_HOLD), whereas simulation.py expects one of 4 corridor actions (BYPASS_LEFT, BYPASS_RIGHT, SAFE_STOP, CONTINUE). Currently, app.py maps SAFE_STOP_AND_HOLD -> SAFE_STOP and defaults all other warehouse actions to BYPASS_LEFT for the corridor 3D view.
